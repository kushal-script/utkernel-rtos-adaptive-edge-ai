# Power

The program plan names power saving as one of the three characteristics the
contest rewards. This records what is implemented, what is measured, and what
is deliberately not claimed.

## The instrument, corrected

The plan says milliwatt level current is measured "via the SMPS on the
H533RE". That is wrong and the wording has been retired: **the STM32H533 has no
SMPS**. There are no SMPS registers in the device header and none in the
reference manual for this part. The claim was carried over from other STM32
families where an SMPS exists.

The measurement point on a NUCLEO-H533RE is the **IDD jumper**, which breaks the
supply to the microcontroller so a meter can be placed in series. It covers the
MCU only, not the ST-LINK, the virtual COM port, or the user LED, so the board
still enumerates and telemetry still streams while a meter is in circuit. Any
figure taken there is MCU current and must never be described as board power.

## The mechanism, which did not previously exist

Measuring first would have produced a null result, because there was nothing to
measure. The kernel's idle hook, `low_pow` in the vendored BSP, shipped as an
empty function body, so the idle task spun at 250 MHz at voltage scale 0. No
amount of gating work upstream could show up as power, because the core never
stopped.

`low_pow` now sleeps. The sequence matters: the dispatcher calls the hook with
`BASEPRI` already raised to mask external interrupts, and a wake up event is
only generated by an exception that would preempt the current execution
priority, which includes `BASEPRI`. A bare `WFI` there sleeps forever, because
the interrupts that should end the idle period are exactly the ones being
masked. That failure was observed on hardware: the first attempt stopped the
system dead. `BASEPRI` is therefore dropped around the `WFI` and restored after.

`PRIMASK` is deliberately not held across the instruction. That is the textbook
sequence, but it leaves no way out if a wake up is missed, whereas simply
reopening `BASEPRI` cannot deadlock: an interrupt arriving before the `WFI` is
taken immediately, and the next one ends the sleep. The whole path is behind
`KWS_IDLE_SLEEP` in `app_config.h` so it can be switched off in one place.

## What is measured today

The idle hook accumulates the cycles spent asleep, in 64 bits because the cycle
counter wraps roughly every 17 seconds at this clock. The benchmark reports the
fraction of wall time the core was idle over the settle window.

| Quantity | Measured |
| :-- | --: |
| Idle residency | 82.3 percent of wall time |
| Sleep entries | 596 over 4.3 s |

That is a genuine, on device measurement of the quantity the power argument
rests on: the core is asleep for most of wall time rather than spinning. It is
**not** a wattage. Converting it to milliwatts would require datasheet typicals
for run and sleep current, and such a number would be modelled rather than
measured, so it is not presented here.

## What would close the axis properly

A DC ammeter in series at the IDD jumper, average current over a fixed length
replay in three configurations, static FP32, static INT8, and adaptive, on the
corpus that contains silence so the gate is exercised. Report average current
and energy per classification. Until that is done the honest statement is the
one above: the mechanism exists, the idle fraction is measured, the current is
not.
